# 各章节"不涉及"判断指南

当用户提供的材料和信息不足以支撑某个章节的编写时，需要判断该章节是否"不涉及"。以下是判断规则和"不涉及"/"无"的标准写法。

---

## 判断原则

1. **不涉及**：该章节的内容与本次架构方案完全无关（例如：不涉及系统迁移时，第8章标记为"不涉及"）
2. **无**：该章节有涉及但无需额外说明（例如：无额外成本时，第11章写"无"）
3. **待补充**：该章节有涉及但信息不足，需要向用户追问

---

## 各章节判断规则

| 章节 | "不涉及"条件 | "无"条件 | 需追问条件 |
|------|-------------|---------|-----------|
| 1 系统概述 | 永不适用（必须编写） | - | 信息不足时追问 |
| 2 业务需求 | 永不适用（必须编写） | - | 信息不足时追问 |
| 3 假设和约束 | 无假设和约束时写"无" | 无 | - |
| 4 现状分析 | 全新系统无现状时写"不涉及" | - | 信息不足时追问 |
| 5 应用架构 | 永不适用（必须编写） | - | 信息不足时追问 |
| 6 技术架构 | 无技术组件变更时写"不涉及" | - | - |
| 7 数据架构 | 无数据设计变更时写"不涉及" | - | - |
| 8 迁移方案 | 不涉及系统/业务迁移 | - | 用户不确定时追问 |
| 9 安全架构 | 永不适用（至少写安全定级） | - | 信息不足时追问 |
| 10 基础架构 | 不涉及基础架构变更时写"不涉及" | - | - |
| 11 成本预估 | 无额外付费资源时写"无" | 无 | - |
| 12 运维架构 | 永不适用（至少写运维等级） | - | 信息不足时追问 |
| 13 附录 | 无需额外附录时写"无" | 无 | - |

---

## "不涉及"标准写法

当某章整体不涉及时，在章节标题下写：

```
本章不涉及。
```

当某章的子节不涉及时，在子节标题下写：

```
本节不涉及。
```

## "无"标准写法

当某章有涉及但无具体内容时：

```
无
```

---

## 必须编写的章节（不可标记为"不涉及"）

以下章节必须编写，不可标记为"不涉及"：
1. 第1章 系统概述
2. 第2章 业务需求
3. 第5章 应用架构
4. 第9章 安全架构（至少包含安全定级）
5. 第12章 运维架构（至少包含运维等级）
